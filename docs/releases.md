# Releases

## Creating a Release

Releases are automated via GitHub Actions and triggered by git tags. The
`release.yml` workflow is generated by [cargo-dist](https://opensource.axo.dev/cargo-dist/)
from `dist-workspace.toml`; regenerate it with `dist generate` instead of
editing it by hand.

In a single `release: X.Y.Z` commit:

1. Bump `version` in `Cargo.toml`.
2. Run `cargo update -p todo` to update `Cargo.lock`.
3. Move the `[Unreleased]` entries in `CHANGELOG.md` to a new dated version section.

Then push `main` and push the tag:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

The workflow automatically:
- Builds archives for Linux (static musl) and macOS (amd64, arm64)
- Builds a shell installer
- Creates a GitHub release with the archives, installer and checksums
- Publishes the Homebrew formula to `juanibiapina/homebrew-taps`

After pushing the tag, the coding agent should:
1. Wait for the GitHub Actions workflow to complete successfully
2. Use `gh release view` to verify the release was created

## Version Format

Follow [semantic versioning](https://semver.org/):

- **Production**: `v1.2.3`
- **Pre-release**: `v1.0.0-beta.1`, `v1.0.0-rc.1`, `v1.0.0-alpha.1`

Pre-release tags (containing `-`) are marked as pre-releases on GitHub and do not update the Homebrew formula.
